# Objection handling

Objections are requests for more information dressed up as "no". Respond to the underlying concern, not the surface words.

## The four-step response

1. **Acknowledge** — restate the objection in the prospect's words so they feel heard. Never say "I understand" without proving it.
2. **Clarify** — ask one question that isolates the real concern. "Is it the price itself, or the timing of the spend?"
3. **Respond** — one relevant proof point: a customer story, a number, or a demo. One, not three.
4. **Confirm** — check whether the concern is resolved and move to the next step. "Does that address it, or is there something else holding you back?"

## Common objections and the concern underneath

| Objection | Usually means |
|-----------|---------------|
| "Too expensive" | Value is unclear, or budget owner is someone else |
| "Not the right time" | No internal urgency; nobody is accountable for the problem yet |
| "We already use X" | Switching cost fear; ask what X does badly |
| "Send me some info" | Polite exit; ask what specifically they want to see |
| "Need to talk to my team" | You have not met the decision maker |

## When drafting a response for the user

- Ask what the prospect said verbatim and what stage the deal is in.
- Draft the reply as the user would say it, in their voice, under 120 words.
- Offer one follow-up question to ask if the first response does not land.
- Never invent customer names, statistics or case studies. Use placeholders like `[customer]` and tell the user to fill them in.
